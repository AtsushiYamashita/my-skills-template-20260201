# Documentation Language Rules

このドキュメントでは、プロジェクト内のドキュメントやアーティファクトで使用する言語に関するルールを定義します。

## アーティファクト言語ルール

### walkthrough.md

**言語**: 日本語

**理由**:

- プロジェクトの主要メンバーが日本語話者
- 実装の詳細を母国語で正確に理解・共有するため
- レビューとフィードバックの効率化

**適用範囲**:

- タスク完了後に作成される `walkthrough.md` の本文
- 実装内容の説明
- 検証結果の記述
- 使用例とサマリー

**例外**:

- コードブロック内のコマンドやコメント（技術的必要性により英語可）
- ファイル名やパス
- 技術用語で日本語訳が不自然な場合（そのまま英語で記載可）

---

### その他のアーティファクト

#### implementation_plan.md

**言語**: 英語または日本語（プロジェクトの文脈に応じて選択）

#### task.md

**言語**: 英語または日本語（チェックリスト項目は簡潔な記述を優先）

## コードドキュメント

### ソースコード内のコメント

**言語**: 英語推奨（国際的な協業を考慮）

### README.md

**言語**: 英語（オープンソースプロジェクトの標準慣例）

### 技術ドキュメント (.agent/rules/, .agent/workflows/)

**言語**: 英語（再利用性と汎用性を考慮）

## AI エージェントへの指示

### Walkthroughアーティファクト作成時

タスク完了時に `walkthrough.md` を作成する際は、以下を遵守してください：

1. **本文は日本語で記述する**
2. **セクション構成**:
   - 変更内容の説明
   - 実行したGit操作
   - 検証結果
   - 使用例
   - 実装ノート
   - サマリー

3. **コードブロックの扱い**:

   ```bash
   # コマンド例（英語のまま）
   git checkout develop
   ```

   説明文は日本語で記述

4. **技術用語**:
   - 一般的な用語: そのまま英語（例: branch, commit, merge）
   - 文脈が必要な場合: 日本語で説明を追加
